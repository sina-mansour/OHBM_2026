## Summary

[**SpectraNorm**](https://sina-mansour.github.io/spectranorm/) is a free and open-source Python package designed to simplify and automate the mathematical foundations of spectral normative modelling. The goal of the project is to provide an accessible, flexible, and scalable framework for normative modelling of phenotypes ranging from conventional low-dimensional measures to high-dimensional neuroimaging and connectomic data.

During OHBM BrainHack, we will share the current state of the software, demonstrate its capabilities through practical examples, and engage with the community to gather feedback that will help guide future development. We welcome researchers interested in normative modelling, neuroimaging methods, software development, documentation, or open science to join the discussion and contribute ideas.

## Goals and activities

Potential focus areas for the hackathon:

- **Gather feedback** on usability, workflows, and user experience
- **Identify gaps** in the current documentation and develop plans for improving tutorials, guides, and examples

## Who should join

We welcome contributors with a wide range of backgrounds and experience levels — from researchers who are simply curious about normative modelling and would like to learn more, to experienced methods developers interested in contributing to an open-source software project.

While no advanced expertise is required, some familiarity with Python would be helpful for participants interested in testing the package, exploring examples, or contributing code. Skills that would be particularly valuable include:

- **Python programming** and scientific computing
- **Neuroimaging data analysis** and normative modelling applications
- **Documentation development**, particularly with MkDocs and related tooling
- **Linear algebra, spectral methods,** and mathematical modelling
- **Probabilistic programming** and statistical modelling
- **Software testing**, usability assessment, and user experience feedback

We are particularly interested in feedback from *potential users* of the package, so participants without a strong methods background are also encouraged to join and help shape the future direction of the project.

### Good first issues

If you'd like to contribute but aren't sure where to start, here are some entry points:

- Read through the documentation and report any unclear sections, typos, or missing explanations
- Test the package on your own dataset (or example data) and share feedback on usability and outputs
- Run the provided tutorials/notebooks and suggest improvements or additional examples
- Open issues for any installation problems or dependency conflicts you encounter
- Help improve documentation by adding missing use cases or clarifying expected inputs/outputs
- Suggest additional features or workflows that would make the package easier to use in practice
- Check example outputs for consistency and help identify potential bugs or edge cases
